# 개발 원칙

사내 시스템(운영 화면, 대시보드, 데이터 탐색기)을 만들 때 지키는 원칙. 디자인 규칙(`AGENTS.md`)이 "어떻게 보이나"라면, 이 문서는 "어떻게 만드나"다. 사람이 짜든 LLM이 짜든 같은 기준을 적용한다.

## 1. 기본 원칙 10

1. **통일이 개성보다 우선한다.** 화면은 `tokens.css` + `ds.css` + `DSCharts`로 만든다. 없는 패턴이 필요하면 먼저 이 레퍼런스에 추가하고(PR), 그다음 시스템에서 쓴다. 시스템마다 따로 만들지 않는다.
2. **빌드 없이 돌아가는 것을 기본으로 한다.** 정적 HTML + CSS + 바닐라 JS로 되는 화면은 그렇게 만든다. 프레임워크·번들러는 그것 없이는 못 만드는 이유가 있을 때만, 이유를 README에 적고 쓴다.
3. **재현 가능해야 한다.** 외부 CDN을 런타임에 참조하지 않는다. 외부 라이브러리는 버전을 고정해 `vendor/`(또는 사내 서버)에 두고, lockfile을 커밋한다. 같은 커밋이면 1년 뒤에도 같은 화면이 나와야 한다.
4. **집계는 데이터 쪽, 표시는 브라우저.** 합계·그룹·정렬은 SQL(서버 또는 DuckDB-WASM)에서 하고 브라우저는 결과를 그린다. 브라우저에서 5,000행 넘게 돌리는 for 문이 보이면 설계를 다시 본다.
5. **모든 화면은 네 가지를 통과한다.** 라이트/다크, 720px 폭, 키보드만으로 조작, 차트의 표 뷰. 하나라도 빠지면 미완성이다.
6. **상태는 URL에 둔다.** 필터·드릴 경로·선택 탭처럼 다시 열고 공유할 상태는 URL 해시나 쿼리에 넣는다. 뒤로가기와 북마크가 동작해야 한다. 비밀값(토큰, 개인정보)은 절대 URL에 넣지 않는다.
7. **실패와 비어 있음을 보여준다.** 로딩, 빈 결과, 오류 세 상태를 모두 설계한다. 재조회 중에는 이전 화면을 흐리게 유지하고(`is-refreshing`), 스켈레톤을 번쩍이지 않는다. 오류 메시지는 무엇이 잘못됐고 무엇을 하면 되는지 쓴다.
8. **빠르게 느껴져야 한다.** 첫 화면 1초, 클릭 반응 100ms, 필터 변경 후 차트 갱신 300ms를 목표로 한다. 느리면 집계를 서버로 옮기거나, 행을 줄이거나(상위 N + 기타), 표를 가상화한다.
9. **입력은 전부 신뢰하지 않는다.** 사용자·API·CSV에서 온 문자열은 `textContent`로만 DOM에 넣는다. `innerHTML`에 문자열을 이어 붙이지 않는다. 가능하면 CSP를 켠다. 자격증명은 코드와 리포 밖(`.env`, 비밀 저장소)에 둔다.
10. **접근성은 기능이다.** 대비 4.5:1(본문)·3:1(큰 글자·그래픽), 보이는 포커스, 아이콘 버튼에 `aria-label`, 상태는 색+아이콘+텍스트. 차트 값은 툴팁 없이도 닿아야 한다(직접 라벨 또는 표 뷰).

## 2. LLM과 함께 개발할 때

- **규칙을 먼저 먹인다.** 코딩 에이전트는 리포의 `AGENTS.md`(= `CLAUDE.md`)를 읽는다. 채팅형 모델에는 `prompts/system-prompt.md`(작은 모델은 `-short`)를 붙인다. 규칙 없이 "예쁘게 만들어줘"라고 하지 않는다.
- **모델이 라이브러리를 고르게 하지 않는다.** 차트는 `DSCharts` → 부족하면 ECharts + `integrations/echarts-theme.js`. 표는 `.ds-table` → 대용량이면 AG Grid + `integrations/ag-grid-theme.js`. 피벗은 Perspective. 그 밖의 선택은 사람이 한다.
- **파일은 모델이 직접 가져오게 한다.** 손으로 복사해 붙이지 않는다. 번들 링크(`api/dist/ds.css`, `ds.js`), `api/install.sh`, `api/manifest.json` 중 하나를 프롬프트에 넣는다. 레퍼런스 사이트의 "프롬프트" 버튼이 이걸 자동으로 넣어 준다.
- **생성된 코드도 같은 리뷰를 받는다.** 아래 "완료 기준"을 사람이 짠 코드와 똑같이 적용한다. 모델이 "확인했다"고 말한 것은 확인된 것이 아니다. 렌더 테스트(`npm test`)와 `grep -n "#[0-9a-fA-F]\{3,6\}"`로 직접 본다.
- **좋은 결과는 예시로 쌓는다.** 승인된 화면은 `examples/`에 넣는다. 다음 생성의 품질은 규칙보다 예시가 끌어올린다.
- **한 번에 한 화면.** 모델에게 시스템 전체를 한 번에 시키지 않는다. 페이지 템플릿(목록/상세/대시보드/설정/탐색기, `docs/04-layout.md`) 단위로 요청하고 합친다.

## 3. 저장소 규칙

- **브랜치 → PR → CI 통과 → 머지.** main에 직접 푸시하지 않는다. CI는 토큰 JSON 일치, 차트 팔레트 색약 검증, vendor/api 생성, 예시 페이지 렌더 24조합(라이트/다크 × 데스크톱/모바일, 콘솔 에러·가로 스크롤)을 본다.
- **토큰 변경은 별도 PR.** `tokens/tokens.css`만 고치고 `npm run tokens && npm run validate:palette`를 통과시킨다. 시리즈 색 순서는 색약 안전성 장치이므로 바꾸면 반드시 재검증한다.
- **버전은 semver 태그.** 깨지는 변경(클래스 이름·토큰 이름·DSCharts 옵션 제거)은 메이저. `package.json`의 version이 `api/manifest.json`에 실린다. 깨지는 변경은 PR 설명에 "마이그레이션" 절을 쓴다.
- **커밋 메시지는 한국어 한 줄 요약 + 필요하면 본문.** 무엇을 왜 바꿨는지. 파일 이름 나열은 git이 한다.
- **문서는 코드와 같은 PR에서 고친다.** 클래스나 옵션이 바뀌면 `docs/`, `AGENTS.md`, `api/charts.json`(생성 스크립트)이 같은 커밋에서 따라간다.

## 4. 코드 스타일

- **JS**: ES2020, 모듈 번들러 없이 `<script>`로도 돌아가게. 전역은 라이브러리당 하나(`DSCharts`, `DSTheme`, `DSEchartsTheme`). 데이터는 객체 배열(`[{...}]`), 날짜는 ISO 문자열(`2026-11-08`). 2칸 들여쓰기, 세미콜론, 작은따옴표. 주석은 한국어로 "왜"를 쓴다.
- **CSS**: 색·글꼴·간격·반경은 토큰만. 클래스는 `ds-블록__요소--변형`, 상태는 `is-active`·`is-invalid`처럼 `is-*`. 컴포넌트 CSS에 미디어 쿼리는 720px 하나를 기본으로. `!important` 금지.
- **HTML**: 시맨틱 태그(`header/nav/main/aside/table`), 모든 폼 컨트롤에 `id`와 `label`, 버튼은 `<button type="button">`, 링크는 `<a href>`. 아이콘은 인라인 SVG, 이모지 금지.
- **데이터 접근**: 조회는 `fetch` + JSON, 큰 데이터는 CSV/Parquet → DuckDB-WASM(`integrations/mosaic-setup.js` 패턴). SQL은 파라미터 바인딩, 문자열 이어 붙이기 금지. 집계 컬럼은 `::DOUBLE`로 캐스팅(BIGINT 합계가 JS에서 깨진다).
- **파일 배치**: `tokens/ css/ js/ integrations/`는 디자인 시스템, `examples/`는 조립 예시, `docs/`는 사람이 읽는 설명, `prompts/`는 모델이 읽는 규칙, `scripts/`는 빌드·검증, `tests/`는 렌더 테스트.

## 5. 완료 기준 (Definition of Done)

머지 전에 전부 "예"여야 한다. 모델이 만든 코드도 같다.

- [ ] hex/rgb 직접 지정이 없다 (`grep -n "#[0-9a-fA-F]\{3,6\}" *.html *.css *.js`가 비어 있다)
- [ ] `.ds-shell__header`가 있고 배경이 `--shell-bg`다
- [ ] 라이트/다크 둘 다 읽힌다 (`DSTheme.toggle()`로 눌러 봤다)
- [ ] 720px 폭에서 가로 스크롤이 없다
- [ ] 키보드(Tab/Enter/Esc)만으로 주요 동작이 된다, 포커스가 보인다
- [ ] 모든 차트에 제목·단위·표 뷰가 있고, 파이·도넛·이중축이 없다
- [ ] 상태 배지에 아이콘과 텍스트가 모두 있다
- [ ] 로딩·빈 결과·오류 상태가 있다
- [ ] 사용자 입력이 `innerHTML`로 들어가지 않는다
- [ ] 외부 CDN 참조가 없다 (`vendor/` 또는 사내 경로)
- [ ] 다시 열어도 같은 화면이 나온다 (필터·경로가 URL에 있다)
- [ ] `npm test`(렌더 테스트)가 통과한다
- [ ] 바뀐 클래스·옵션이 문서와 `AGENTS.md`에 반영됐다

## 6. 하지 않는 것

- 시스템마다 다른 버튼·표·색을 "조금만" 바꾸는 것. 바꾸고 싶으면 레퍼런스를 바꾼다.
- 모델 출력물을 보지 않고 커밋하는 것.
- 데모용 더미 데이터를 운영 코드에 남기는 것. 예시 데이터는 `examples/data/`에만.
- "나중에 다크 모드 추가". 토큰만 쓰면 처음부터 된다.
- 성능 문제를 로딩 스피너로 가리는 것.
