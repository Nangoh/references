# 01. 원칙

## 정체성

이 시스템으로 만든 화면은 열자마자 "같은 회사 시스템"으로 읽혀야 한다. 그 인상을 만드는 요소는 네 가지이고, 네 가지 모두 토큰과 `ds.css`에 고정되어 있어서 따로 신경 쓸 필요가 없다.

| 요소 | 값 | 어디에 고정 |
|---|---|---|
| 액센트 | 페트롤 틸 (`--accent`, OKLCH hue 210) | `tokens.css` 브랜드 램프 |
| 상단 셸 | 48px, 라이트·다크 무관하게 항상 어두운 페트롤 (`--shell-bg`) | `.ds-shell__header` |
| 글꼴 | IBM Plex Sans KR + IBM Plex Mono | `--font-sans`, `--font-mono` |
| 밀도 | 본문 14px, 컨트롤 32px, 표 행 36px, 반경 6px, 카드 그림자 없음 | `ds.css` |

흔한 파랑·보라·주황을 피해 틸을 골랐고, 다들 쓰는 Pretendard·Noto 대신 Plex를 골랐다. 둘 다 "식별되는 것"이 목적이다. 둥글고 큼직한 소비자 앱 느낌은 의도적으로 배제했다. 우리 화면은 하루 종일 보는 운영 도구다.

## 다섯 원칙

1. **일관이 개성보다 앞선다.** 한 화면이 조금 더 예뻐지는 것보다 열 개 시스템이 같아 보이는 것이 가치가 크다. 컴포넌트를 변형하고 싶으면 `ds.css`를 고쳐 모두에게 적용한다. 한 곳에서만 다르게 만들지 않는다.
2. **데이터가 가장 큰 소리를 낸다.** 크롬(테두리, 그리드, 배경, 장식)은 가라앉고 숫자와 마크만 또렷하다. 카드 그림자, 두꺼운 그리드, 채도 높은 넓은 면을 쓰지 않는 이유다.
3. **상태는 형태와 색으로 함께 말한다.** 성공·경고·위험은 색 + 아이콘 + 텍스트 셋이 항상 같이 간다. 색약 사용자, 흑백 인쇄, 고대비 모드에서도 의미가 남아야 한다.
4. **두 테마는 동등하다.** 다크 모드는 라이트의 반전이 아니라 같은 램프에서 따로 고른 단계다. 차트 색도 라이트·다크 각각 검증기를 통과한 값이다. 라이트만 확인하고 끝낸 화면은 미완성이다.
5. **모델이 추측하지 않게 만든다.** 이 시스템의 1차 사용자는 GPT·GLM·Claude 같은 LLM이다. 글로 된 취향 설명 대신 클래스명, 토큰명, 호출 예시로 규칙을 적는다. 모호한 지점은 "이렇게 하라"로 닫는다. `AGENTS.md`가 그 결과물이다.

## 적용 범위

- **대상**: 사내에서 운영하는 모든 웹 시스템의 화면. 신규는 처음부터, 기존은 `README.md`의 적용 순서(토큰 → 셸 → 컴포넌트 → 차트)로 점진 전환한다.
- **포함**: 색·타이포·간격·반경 토큰, 앱 셸과 컴포넌트, 일반 차트(`DSCharts`), 탐색형 차트 통합(ECharts, Mosaic, Perspective, AG Grid), LLM 프롬프트.
- **제외**: 아이콘 세트(각 시스템이 쓰는 것을 유지하되 16px·`currentColor`만 지킨다), 마케팅·대외 랜딩 페이지, 모바일 네이티브.
- **우선순위**: 사용자의 명시적 요구 > 이 시스템 > 모델의 판단. 사용자가 규칙에 어긋나는 요구를 하면 한 줄로 알리고 요구대로 만든다.
